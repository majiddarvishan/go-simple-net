Option B remains: no production source edits or new hot-path bookkeeping in normal builds. New external source overlay `scripts/qa005_owned_buffers_overlay.py` injects Session-mutex-protected accounting only into the benchmark's **temporary compile view** of four existing Go files. Original pinned QA004-QA005-SOURCE-V1 `9b7b2318f73d173a99d22489042f84f8ce58b745` is untouched; the script rejects output inside the checkout and hashes every original/effective overlaid source.

- F1: outgoing Stream frame backing slice now counted on allocation inside the V2 SendRequest/SendNoWait/SendResponse overlay, before Queue admission, and released once on write, Close or rejected-frame rollback. Queue/Writer transfer is non-additive.
- F2: one inbound Stream Request Body backing slice, counted immediately after `make`, released only when Application retention charge finishes (callback return or cancel).
- F3: one inbound matched Stream Response Body backing slice, counted immediately after `make`, released with Completion charge on return/cancel.
- F4: outgoing Control frame backing slice, counted on enqueue, released after write or cancel/close.
- Use `cap(buffer)` in bytes for these byte slices. Buffer capacity is a requested Go backing allocation size, **not** the runtime allocator's physical size.
- Existing Session mutex protects counters and frame/charge release flags. Bench-only observer walks Server live-session map under its mutex, unlocks, then snapshots each Session under its own mutex, plus all client Sessions. Never nest Server and Session mutexes. The global sampled sum may be skewed and miss fast peaks.
- Quota reservations, Incoming queue charges, current/external user slices, callback closure graphs, Pending/Worker metadata, Panic raw object graphs, transient unclassified Bind/Control read buffers, runtime overhead, goroutine stacks and GC are **not included**. No claim of total neta heap attribution.

The diagnostic metric is **`probe-owned-buffer-peak-B`**, with `probe-owned-buffer-samples` and earlier charge probe metrics. It is *never* `retained-attributed-B`; no mandatory acceptance decision may use it until category coverage, sample-window validity, density, overflow handling, deterministic lifecycle tests and instrumented-vs-uninstrumented overhead are validated. The generator is strict about expected source anchors; any changed code forces explicit re-review. Go unit tests and one-op smoke may be run in advisory CI only. ## MEM-004G — V8 F5 unreserved inbound Body / V9 reconciliation (2026-11-19)

**V8 F5**: Previously `readFrame` allocated Bind Request/Response Bodies with `make([]byte, bodyLength)` without an Application or Completion charge; those owned slices were omitted even from the partial buffer diagnostic. The test-only adapter now injects a fifth Session-mutex-protected category, `qa005OwnedInboundTransient`, and a `qa005TransientBodyBytes` field on `inboundFrame`. It charges `cap(body)` immediately after allocation when neither applicationCharge nor completionCharge exists; charges F2/F3 unchanged and exclusively. A returned read error releases the transient count in a deferred readFrame cleanup; successful read transfers the amount to the handler and releases it at `handleInboundFrame` return (including protocol errors). No amount is transferred to callbacks or user payloads in this unreserved path. An overlay-only Go net.Pipe test constructs a real V2 Bind frame and verifies both a successfully received Body with terminal handler error and a truncated read that releases immediately; code under `-race` on unchanged original wire/source. This tracks only transient backing storage, NOT decoded Bind strings, scratch arrays, metadata or runtime allocator bucket sizes. Do not extrapolate F5 beyond these paths.

**V9 integrity**: Under each Session mutex, `qa005OwnedConsistentLocked` sums F1 outgoing, F2 incoming request, F3 incoming completion, F4 control and F5 unreserved inbound and compares against the Session-owned total, rejecting overflow, category drift and existing resource faults. Both aggregate sampled buffer diagnostic and independently accumulated Session HWM upper fail closed. New Go test deliberately changes one category without changing total to show both reject the drift, then restores it and verifies normal observation and release. This validates only counter self-consistency, NOT that all runtime memory was attributed.

**Open ownership boundaries**: (1) F4 Control Bind pre-Session allocation and other encoding-before-lock gaps cannot be assumed to start at Queue admission; (2) M1 `pending` map entries, the Session struct, outboundFrame and charge metadata, queue slice backing arrays and dispatcher Worker/Task allocations have shared/variable runtime representation; do not equate `len(map)` or `cap(slice)` with physical object ownership; (3) D1 Panic diagnostic first/recent records, formatted strings, raw panic or user closure graphs can retain external objects of unknown ownership. These cannot be reported as measured zero and remain scope/coverage blockers; any future byte measurement needs a separately reviewed ownership-count and alias-dedup contract.
